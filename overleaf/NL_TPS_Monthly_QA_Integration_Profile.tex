\NLFrontMatterSection{Executive summary}

The reviewed Monthly QA implementation is a useful evidence and visualization prototype. It contains read-only extractors, longitudinal QA records, detector-specific provenance, commissioning candidates, Daily QA protocol-era separation, explicit missing-data behavior, local retrieval corpora, and a modern web explorer. Those capabilities can accelerate NL-TPS realization when they are placed behind the suite's existing governance, evidence, safety, security, state, audit, operations, and verification controls.

The implementation shall enter the NL-TPS as \textbf{MQA-PKG-01 Machine QA Evidence and Readiness Integration}, a domain package composed of existing controlled components. It shall not become a second planning authority, a replacement for source QA records, an automated QMP, or a retrieval-driven pass/fail engine. A signed, versioned readiness assertion may be consumed by the deterministic safety kernel only after the applicable QA evidence, approved rule, configuration, review, and return-to-service state have been reconciled.

\begin{nlnotice}{NON-NEGOTIABLE CLINICAL BOUNDARY}
The machine-QA subsystem may collect, normalize, display, compare, route, and preserve evidence. It may calculate a deterministic comparison using an approved computable rule. It shall not approve a procedure or tolerance, sign a QA result, waive a discrepancy, declare a machine safe, authorize return to service, approve a plan, or command treatment delivery. Retrieval and generative models shall not perform pass/fail or readiness adjudication.
\end{nlnotice}

\section{Purpose and scope}

This profile defines the controlled integration of Daily, Monthly, Annual, commissioning, maintenance-context, detector, and supporting QA evidence into the NL-TPS. It translates the reviewed prototype into requirements, interfaces, component allocations, data objects, workflows, risks, trade-off decisions, verification obligations, and implementation phases.

\subsection{In scope}

\begin{itemize}
\item Read-only acquisition from approved workbooks, reports, databases, DICOM objects, detector exports, and other commissioned source adapters.
\item Canonical machine-QA observations with explicit units, configuration, protocol, tolerance, uncertainty, provenance, and lifecycle state.
\item Longitudinal review, source drill-down, missing-evidence identification, protocol-era separation, and pre/post-maintenance comparison.
\item QMP-controlled procedure, tolerance, reference, deviation, corrective-action, approval, expiry, and return-to-service workflows.
\item Publication of a minimal signed machine-readiness assertion to the NL-TPS safety and proton-profile services.
\item Natural-language query and draft-workflow support within the existing typed-intent and confirmation boundary.
\item DICOM and external-TPS association only through commissioned, allowlisted interfaces.
\end{itemize}

\subsection{Out of scope}

\begin{itemize}
\item Autonomous approval of measurements, tolerances, procedures, references, deviations, or machine readiness.
\item Substitution of statistical models, retrieval results, dashboards, or normalized data for authoritative source records.
\item Silent conversion of a commissioning candidate, embedded expected value, historical baseline, or literature value into an approved clinical tolerance.
\item Fabrication or imputation of missing measurements, dates, configurations, evidence files, or approvals.
\item Direct treatment delivery, machine control, plan approval, QA waiver, or return-to-service action by AI or a service account.
\end{itemize}

\subsection{Reusable strengths}

\begin{itemize}
\item Source-read-only and idempotent extraction intent.
\item Explicit differentiation among measured values, embedded expected values, tolerances, and commissioning candidates.
\item Source workbook, worksheet, cell, PDF page, raw-directory, raw-file, detector, date, and calculation-method locators.
\item Preservation of repeated observations and configuration facets rather than silent averaging.
\item Protocol-era separation and explicit structured-data gaps.
\item Candidate, method-approval-required, and inventory-only commissioning states.
\item Offline retrieval, source hashing, DICOM identifier redaction, excluded PLD patient columns, and metadata-only handling of proprietary binaries.
\item Deterministic statistical functions and clear exploratory-use labeling for normal and Monte Carlo views.
\end{itemize}

\subsection{Gaps requiring controlled redesign}

\begin{itemize}
\item Application authentication, role authorization, electronic approval, immutable audit logging, deviation/CAPA workflow, and return-to-service gating are not implemented in the prototype.
\item Large static JSON files are bundled with application code; Monthly/Annual data are passed to client components rather than queried through an authorized server boundary.
\item Evidence records retain paths and filenames but are not directly bound to the RAG manifests' source hashes.
\item Source paths, release expectations, record counts, transformation exceptions, and some reference mappings are encoded in scripts.
\item Browser workbook loading accepts broad file extensions and performs only limited structural validation without a clinical schema signature, file-size limit, malware control, or resource sandbox.
\item The health endpoint proves process liveness but not data integrity, evidence currency, configuration compatibility, or dependency readiness.
\item The repository-wide lint command includes temporary browser-profile content; application-scoped source lint succeeds, but the release command is not currently reproducible without an ignore correction.
\end{itemize}

\section{Architecture and interface allocation}

\subsection{Target data flow}

The target architecture uses an asynchronous evidence-ingestion path and a minimal synchronous readiness path:

\begin{enumerate}
\item Approved source adapters read controlled archives without modifying them.
\item C-JOB-01 records an atomic import run and C-SEC-01 applies the approved parsing and privacy boundary.
\item C-TERM-01 and C-RULE-01 validate terminology, units, transformations, applicability, and approved comparison rules.
\item C-OBJ-01 stores immutable canonical versions; C-PROV-01 links source, transform, configuration, review, and downstream impact; C-AUD-01 records actions and decisions.
\item C-UX-01 presents observations, gaps, source evidence, trends, and review tasks to authorized users.
\item C-IAM-01, C-STATE-01, C-QMS-01, and C-INC-01 control review, approval, deviations, CAPA, and closure.
\item C-PBT-01 publishes the applicable signed readiness assertion to C-SAFE-01. The evidence explorer itself is not a synchronous treatment-planning dependency.
\end{enumerate}

\subsection{DICOM and existing-TPS boundary}

DICOM shall be used when a QA source is a valid DICOM object or when QA evidence must be associated with commissioned clinical objects. The subsystem shall not create synthetic DICOM objects merely to transport spreadsheets, reports, Access records, or proprietary detector formats. Those artifacts remain evidence objects in the canonical repository and may reference DICOM identifiers when a validated association exists.

Each external-TPS route shall have a site- and version-specific conformance analysis, transaction and object allowlist, identity and UID reconciliation, private-attribute policy, timeout and retry behavior, negative tests, known limitations, monitoring, and rollback. An undocumented private field or inferred equivalence shall not become a silent dependency.

\subsection{Readiness states}

Readiness is a separate object from evidence review. \textbf{Unknown} means the applicable state cannot be established. \textbf{Hold} means an approved rule requires clinical-use restriction. \textbf{Conditional} means a specifically authorized limited scope and condition exist. \textbf{Released} means all applicable prerequisites and QMP authorization are current. \textbf{Expired} means the effective interval ended. Every state shall identify exact machine/configuration scope and shall be consumed through C-SAFE-01 rather than inferred from dashboard color or record count.

\section{Verification and acceptance}

\subsection{Locked reference and challenge set}

The initial controlled test library shall include, at minimum:

\begin{itemize}
\item representative GTR4 and GTR5 Daily, Monthly, Annual, and commissioning records;
\item pre-maintenance, post-maintenance, routine, missing-month, raw-only, and protocol-transition examples;
\item output, flatness, symmetry, range, spot size, spot position, mechanical, imaging, and detector-specific configurations;
\item exact boundary, just-inside, just-outside, unit-conversion, rounding, and no-applicable-rule cases;
\item missing raw evidence, blank template formulas, duplicate observations, repeated measurements, inconsistent dates, wrong room, wrong configuration, and corrupted or unsupported files;
\item candidate, method-pending, inventory-only, approved, expired, suspended, and superseded reference states;
\item unauthorized approval, incompatible self-review, prompt injection, embedded document instructions, and attempted AI return-to-service actions;
\item DICOM wrong-patient, wrong-study, wrong-frame, orphaned reference, duplicate, partial, timeout, and destination-reconciliation cases;
\item maintenance, repair, software upgrade, rollback, data restore, degraded mode, invalidation, retest, and return-to-service scenarios.
\end{itemize}

\subsection{Release gates}

MQA-PKG-01 shall not influence clinical readiness until:

\begin{enumerate}
\item The source inventory, authority, privacy, retention, ownership, and integrity baseline are approved.
\item Canonical schemas, terminology, units, transformations, procedures, tolerances, and effective-date rules are controlled and traceable.
\item Every released adapter is source-read-only, resource-bounded, signed, independently reviewed, and tested against locked evidence.
\item Authentication, role authorization, electronic signatures, separation of duties, audit integrity, deviation/CAPA, and return-to-service workflows are verified.
\item Retrieval and analytics are demonstrably isolated from pass/fail, readiness, approval, and treatment authority.
\item Readiness invalidation, expiry, hold, degraded operation, rollback, backup, restore, and reconciliation are verified end to end.
\item Each DICOM/TPS route passes conformance, object, transaction, identity, UID, frame, unit, private-field, round-trip, and destination tests.
\item Representative users complete formative and summative human-factors testing for source authority, gaps, warnings, protocol eras, candidate references, confirmations, and recovery.
\item Retrospective and shadow-mode results meet approved accuracy, completeness, false-positive, false-negative, availability, latency, security, and user-burden thresholds.
\item The QMP, clinical governance, quality, security/privacy, informatics, operations, and independent V\&V authorities approve residual risk and the released scope.
\end{enumerate}

\section{Controlled implementation sequence}

\begin{enumerate}
\item \textbf{Baseline and freeze.} Inventory a representative evidence package, record hashes and authority, confirm August 2026 and later source status directly from the controlled share, and preserve a locked test snapshot.
\item \textbf{Control the information model.} Approve canonical objects, terminology, units, protocol and tolerance schemas, transformations, lifecycle states, and source-authority rules.
\item \textbf{Harden ingestion.} Convert extractors into signed configuration-driven jobs with atomic output, resource limits, privacy controls, integrity linkage, and reconciliation reports.
\item \textbf{Deploy read-only exploration.} Reuse the strongest chart, configuration, gap, and source-drill-down patterns through authenticated server APIs in a segregated mode.
\item \textbf{Add human governance.} Implement role-based review, signatures, procedure/tolerance approval, deviations, CAPA, expiry, and audit reconstruction.
\item \textbf{Publish readiness.} Implement the minimal signed readiness assertion, deterministic safety-kernel consumption, invalidation, hold, degraded operation, and QMP return to service.
\item \textbf{Add natural-language support.} Release allowlisted query and draft-workflow intents after ambiguity, prohibited-action, prompt-injection, read-back, confirmation, cancellation, and HFE testing.
\item \textbf{Commission external routes.} Add DICOM and TPS associations one site, version, machine, object, and transaction profile at a time.
\item \textbf{Validate and release.} Complete reference/challenge tests, shadow operation, recovery, security, performance, human-factors, site acceptance, residual-risk approval, and governed release.
\end{enumerate}

\section{Definition of done}

The profile is realized only when every MQA requirement and sub-requirement has an approved owner, design allocation, interface contract, hazard and risk trace, implementation, test case, expected result, executed result, anomaly disposition, monitoring signal, rollback method, and release decision. The operational system must be able to reconstruct why an observation was displayed, which source and rule were used, who reviewed it, what readiness scope it affected, and why the resulting state was accepted or blocked.

\textbf{Bottom line.} The prototype is a valuable evidence and interface foundation; clinical use requires a governed, typed, traceable, QMP-owned readiness service. Accountability remains explicit: clinical physics owns technical meaning and return to service; quality owns process/CAPA; systems engineering owns deterministic state/safety; data and security own integrity/privacy; integration owns commissioned DICOM/TPS boundaries; independent V\&V owns release evidence.
